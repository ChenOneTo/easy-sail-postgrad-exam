# 任务「进行中」功能改造方案

> 版本：v1.1（定稿） · 日期：2026-08-25
> 状态：开发中

## 一、需求背景

现有任务仅有「待完成 / 已完成」两态。新增「进行中」状态，用于标记正在执行的任务，
并记录开始时间，为后续统计耗时预留数据基础。

## 二、已确认的设计决策

| 决策点 | 方案 |
|---|---|
| 触发方式 | 任务行/看板卡上专用 **▶ 开始 / ⏸ 暂停** 按钮（checkbox 仍为完成） |
| 数量限制 | 不限制同时进行的任务数 |
| 日历筛选 | 新增独立「进行中」tab（四档筛选） |
| 开始时间 | 改为**开始日期** `startDate`（YYYY-MM-DD）：存储 + 排序 + 展示 + 可编辑；校验规则见 4.3 |

## 三、现状分析

| 层 | 现状 | 影响 |
|---|---|---|
| SQLite 迁移 (`src-tauri/src/lib.rs:84`) | CHECK 约束 v1 起即含 `'doing'` | ✅ 无需状态列迁移 |
| 前端类型 (`src/lib/types.ts`) | `KanbanStatus = 'todo' \| 'done'` | 需扩展 |
| AI 常量 (`src/lib/prompts.ts`) | `KANBAN_IDS = ['todo','done']` | 需扩展 |
| Store (`task-store.ts` toggleTask) | 二态切换，kanban 与 completed 强同步 | 需三态逻辑 |
| 看板视图 (`KanbanBoard.tsx`) | 固定两列 | 需第三列 |
| 日历视图 (`CalendarView.tsx`) | 三档筛选 | 需四档 |
| 详情面板 (`DetailPanel.tsx`) | checkbox 二态 | 需三态 pill |
| AI 聊天 (`AiChat.tsx`、`ai-json.ts`) | completed↔kanban 映射 | 需支持 doing |
| 云同步/导入 (`cloud.ts`、`replaceTasks`) | 整体透传无校验 | 补白名单兜底 |

## 四、数据模型

### 4.1 类型扩展

```ts
// src/lib/types.ts
export type KanbanStatus = 'todo' | 'doing' | 'done';

export interface Task {
  // ...现有字段
  startDate: string | null;   // 开始日期 YYYY-MM-DD，null = 从未开始
}
```

### 4.2 字段联动语义

| 迁移 | kanban | completed | completedAt | startDate |
|---|---|---|---|---|
| todo → doing | doing | false | null | **写入当天**（已有值则保留） |
| doing → todo（暂停） | todo | false | null | **保留** |
| doing/todo → done（勾选或按钮） | done | true | now | **保留** |
| done → todo（取消完成） | todo | false | null | 保留 |

> 设计取舍：取消完成的任务统一回「待完成」，不记忆来源状态。

### 4.3 日期联动规则

- **开始自动顺延（默认）**：点 ▶/状态 pill 切「进行中」时，生效开始日期 = 已有值 ?? 今天；
  若 截止日期 < 生效开始日期 → **截止日期自动改为开始日期**，之后用户可自主延长截止时间
- **编辑开始日期**：不得晚于截止日期，违规时拒绝写入并提示「开始日期不能晚于截止日期」
- **编辑截止日期**：不得早于开始日期（可自由延长），违规时拒绝写入并提示「截止日期不能早于开始日期」
- 清空任一日期视为不约束

## 五、改动清单

### 5.1 Rust 迁移（src-tauri/src/lib.rs）

新增 Migration v4（仿 v2 模式）：

```sql
ALTER TABLE tasks ADD COLUMN start_date TEXT;
```

### 5.2 常量与提示词

- `src/lib/prompts.ts`：`KANBAN_IDS = ['todo', 'doing', 'done'] as const`
- 同文件 AI JSON schema 文案更新 `"kanban":"todo|doing|done"`

### 5.3 数据层（src/lib/db.ts）

- `rowToTask`：读取 `start_date`
- `dbUpdate` fieldMap：加 `startDate → start_date` 映射
- `dbReplaceAll`：INSERT 列清单补 `start_date`（防云恢复静默丢值）

### 5.4 Store 层（src/stores/task-store.ts）

- 新增 `setKanban(id, status)`：统一处理三态迁移及字段联动，开始前校验 `canStartTask`（返回 boolean）
- 新增便捷方法 `startTask(id)` / `pauseTask(id)`
- `toggleTask` 保持二态：勾选 → done；取消 → todo
- `INITIAL_TASKS` / `createTask` 补 `startDate: null`
- `replaceTasks` 规范化：
  - `startDate` 经 normalizeDate 归一为 YYYY-MM-DD
  - kanban 白名单校验，非法值回退 `'todo'`

### 5.5 UI 组件

| 文件 | 改动 |
|---|---|
| `TaskRow.tsx` | actions 区加 ▶/⏸ 按钮（不可开始时置灰+提示）；进行中显示徽标+左边框高亮+开始日期；checkbox 可直接完成 |
| `KanbanBoard.tsx` | COLUMNS 加「进行中」列；过滤改精确三态匹配；统计栏加进行中计数；该列按 startDate 倒序；卡片显示开始日期 |
| `CalendarView.tsx` | 筛选类型扩为 `'all' \| 'pending' \| 'doing' \| 'done'`，新增 tab 及计数 |
| `DetailPanel.tsx` | 状态区改三态 pill 选择器；新增可编辑「开始日期」DatePicker 字段，与截止日期双向校验并提示 |

展示格式复用 `formatDate`（"M月D日"）；校验入口 `canStartTask`（utils.ts）。

### 5.6 AI 集成

- `AiChat.tsx buildTaskUpdates`：支持 `kanban='doing'`（仅 done 置 completed=true）
- `AiChat.tsx renderPatchRows`：看板 patch 显示中文标签
- `ai-json.ts normalizeKanban`：引用 KANBAN_IDS 自动生效

### 5.7 样式（src/index.css）

- `.kanban-col-dot.doing`（蓝色系）
- `.task-row.doing` 高亮、`.badge-doing` 徽标
- `.btn-start` / `.btn-pause` 按钮（复用 btn-delete 结构）

## 六、历史数据处理与兼容性

结论：**零破坏、无需存量数据迁移脚本、新旧版本双向兼容。**

| 存储层 | 处理方式 |
|---|---|
| SQLite 存量行 | 无需 UPDATE；新状态仅在新操作产生 |
| start_date 新列 | ALTER TABLE 自动填 NULL；插件版本表保证迁移只执行一次 |
| localStorage 旧数据 | loadFromDb 规范化覆盖；DB 不可用时 `?? null` 防御性访问 |
| 云同步旧备份 | replaceTasks 白名单 + 兜底归一化 |
| 历史旧库 | 全新项目，不做任何历史数据迁移 |

降级兼容：老版本看板过滤 `!== 'done'`，「进行中」会显示在待完成列——功能降级但
不崩溃、不丢数据；老版 DB CHECK 本就允许 doing 写入，来回切版本无损。

唯一注意：长期停留旧版本的设备与新版互相同步时，进行中任务在旧端显示为普通待办（预期行为）。

## 七、不受影响项（已验证）

QuickAdd 新建仍 todo · localStorage persist 全量 tasks · 旧数据零迁移
