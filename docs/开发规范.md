# 开发规范

> 本文档持续补充，只收录已确认的规范条目；新增条目在文末维护记录中登记。

## 一、图标规范

**一律使用框架图标（lucide-react），任何位置不允许使用 emoji 图标。**

1. **页面 UI**：图标组件从 `lucide-react` 导入，尺寸与现有代码保持一致（导航类 `size={16}`，参考 [Sidebar.tsx](../src/components/Sidebar.tsx) 的用法）。
2. **系统通知文案**：title/body 使用纯文本，不加 emoji 前缀（系统通知本身也无法渲染字体图标）。
3. **存量待清理**：[notification-engine.ts](../src/lib/notification-engine.ts) 中任务提醒标题 `'⏰ 任务提醒'` 为历史遗留，后续统一清理时移除 emoji。

## 二、构建与发布规范

**本项目使用远程 GitHub 打包，不做本地 Rust 编译。**

1. **本地验证范围**：仅前端——`npm run build`（tsc 类型检查 + vite 构建）和 `npm run lint`。这两项通过即视为改动合格。
2. **本地环境无 Rust 工具链配套**：本机未安装 MSVC / Windows SDK，`cargo check`、`cargo build`、`npm run tauri dev` 在本地跑不起来，属正常现象，不要尝试在本机补齐该环境。
3. **Rust 侧改动的验证方式**：以远程 CI 为准。本地可选做轻量语法检查（如 `rustc --edition 2021 --crate-type lib --emit=metadata` 单文件解析，预期只报找不到 crate 的错误）；完整编译验证由 CI 完成。
4. **发布流程**：推送 `v*` 格式标签触发 [.github/workflows/build.yml](../.github/workflows/build.yml)，在 GitHub Actions 上按 Windows / macOS / Linux 三平台矩阵构建并发布安装包。
