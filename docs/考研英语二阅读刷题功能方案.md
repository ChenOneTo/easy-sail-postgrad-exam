> 版本：v1.2（已实施） · 日期：2026-10-31

**方案摘要**

- 新增独立模块 `exam-reading`：题库（5 年 × 4 篇 × 5 题）+ 三档刷题（精读 / 限时单篇 / 套卷）+ 错题本 + 统计。

- 刷题时间按考场口径设计：单篇 15–18 分钟、套卷 70 分钟、建议 14:15 进入阅读块、按 `exam_profile.exam_date` 倒计时排期。
- 复用现有 `xxx-db.ts → xxx-store.ts → XxxPage.tsx` 分层、SQLite 同库分表、云同步独立文件模式；不改动任务/计划/背单词任何现有表。

## 一、需求背景

已落地模块：考研计划（倒计时 + 分科任务）、背单词（5054 词 + FSRS 调度）、单词闯关。英语二还缺**阅读**这一环：

- 阅读 Part A 是英语二分值最高的单块（40/100），也是提分最慢、最需要节奏训练的部分。
- 真题散落在 PDF/纸质书中，做题时无法限时、无法统计每篇用时、错题无法回看。
- 现有背单词解决词汇，但没有「读文章 → 定位 → 排除选项 → 复盘」的完整闭环。

本模块把近 5 年英语二阅读 Part A 做成结构化题库，提供**与考场同口径的计时**、逐题复盘、错题重做和正确率统计，让每天的阅读训练和考试日下午的节奏对齐（当前默认考试日 2026-12-19）。

非目标（本期不做）：

- 完形填空、阅读 Part B 新题型、翻译、写作（后续可复用同一套会话/计时/统计）。
- AI 生成阅读题（真题题库不需要；AI 只作为后续精读讲解能力）。
- 全卷 180 分钟模考（缺少其他题型题库，单独做阅读套卷即可）。

## 二、设计前提

### 2.1 考场时间事实

英语二在考研初试**第一天下午 14:00–17:00**，满分 100 分，时长 180 分钟。管理类联考（199）考生当天上午考管综，下午考英语二，与本项目现有考试日 `exam_profile.exam_date` 的语义一致。

全卷建议时间分配（用于反推阅读训练参数）：

| 部分 | 题量 | 分值 | 建议用时 |
|---|---:|---:|---:|
| 完形填空 | 20 | 10 | 15 min |
| 阅读 Part A | 20 | 40 | 70 min |
| 阅读 Part B（新题型） | 5 | 10 | 15 min |
| 翻译 | 1 | 15 | 20 min |
| 小作文 | 1 | 10 | 15 min |
| 大作文 | 1 | 15 | 30 min |
| 涂卡 / 检查 | — | — | 15 min |
| **合计** | **48** | **100** | **180 min** |

阅读 Part A 的结构与口径：

- 4 篇文章，每篇 5 题，共 20 题；每题 2 分，共 40 分；四选一（A–D）。
- 70 min ÷ 4 篇 = **17.5 min/篇**。因此单篇训练上限取 **18 min**，冲刺档取 **15 min**。
- 按常见做题顺序「完形 15 min → 阅读」，阅读块约在 **14:15–15:25** 开始与结束。这是应用建议开始时间的依据，不强制。

结论：数据源已齐备，不需要从零录入；本期的主要数据工作是 **PDF 原文/题干/选项抽取 + 解析集合并 + 校勘**。

关键事实（决定实现方式）：

1. **解析集不含阅读原文、完整题干和四个选项**，README 已明确声明「阅读原文长篇正文不在本集内」。它给出的是 `**21. [D] on specially designed farms** — 考点：…` 这种「题号 + 正确项文本 + 定位 + 解析 + 干扰项」的复盘材料。因此**不能把 Markdown 直接当题库**：题干、A–D 四个选项、文章段落必须从 PDF 抽取，再与解析集按题号 21–40 合并。
2. 五年答案已做多源核验（README 的「答案可靠性」一节）：2026 无存疑；2025 第 21、30 题存疑（42 为 Part B，不在本期）；2022 第 39 题存在 C/D 版本分歧（采信 C）。这些必须落成 `answer_note` / `disputed` 字段，不能静默选一个。
3. 扫描卷存在 OCR/排版问题，解析集已给出校勘提示：2025 Text 1 有两处 OCR 讹误（`70%`→`20%`、waiters/cooks 句），2025 Text 4 第 1–2 段整段重复（实际 6 段），2023 Text 2 第 29 题选项顺序有转录差异（以试卷为准），2026 Text 1 有逗号粘连。**PDF 抽取后必须过一遍校勘表**，否则原文和定位段号会错。
4. 本期只取 **阅读 Part A（Q21–40）**；完形、Part B、翻译、写作不进入题库。2026 Part B 的官方扫描卷缺段问题不影响本期。
5. 版权：真题原文版权归教育部教育考试院。该目录与生成的题库仅用于个人备考；若要公开发布安装包，需确认授权或改为用户本地导入（见第十节）。

规模：5 年 × 4 篇 = **20 篇**，每篇 5 题 = **100 题**；正文约 400–500 词/篇，合计约 9000 词。5 个解析文件合计约 200 KB，足够支撑逐题复盘。

## 三、设计决策

| 决策点 | 方案 | 理由 |
|---|---|---|
| 模块定位 | 独立 `exam-reading`，7 张新表 | 与任务、背单词、数学刷题方案零耦合，可单独备份/恢复 |
| 题库来源 | 已下载的 5 份解析 Markdown + 8 份试卷 PDF → 半自动抽取校对 → JSON → 首启导入 DB | 解析集已有答案/解析，PDF 有原文/题干/选项，避免从零录入；与词表模式一致 |
| 争议答案 | `disputed` + `answer_alt`，两个答案均判对；复盘显示来源说明 | 2025 Q30 真实存在 C/D 分歧，不静默选边，也不误判用户 |
| 数据校勘 | 校勘表 + 人工复核；`source_ref` 记录 md/PDF 出处 | 扫描卷有 OCR 讹误、重复段落与选项顺序差异 |
| 题型 | 只做阅读 Part A（四选一） | Part B/完形/翻译结构不同，先做最高分值且结构统一的部分 |
| 计时档位 | 精读（不限时）/ 限时单篇（15/18 min）/ 套卷（70 min） | 分别对应一刷理解、二刷节奏、考前模拟 |
| 计时实现 | 墙钟 `deadline_at`，不用 tick 累加；不提供暂停 | 后台节流/休眠/退出都不能让考场计时变慢 |
| 时段匹配 | 建议 14:15 开始（考场阅读块），记录 `in_exam_slot`，非阻断提示 | 匹配生物钟，但不强制上班族只能在下午练 |
| 日期匹配 | 读取 `exam_profile.exam_date`，按剩余天数分三阶段排期 | 与现有考研计划共用考试日，不重复维护 |
| 套卷年份 | 最近 2 年留作套卷，次新 1 年限时，最早 2 年精读 | 最新真题最接近考场，必须留到考前 |
| 统计口径 | 默认「首刷」；可切换「含重做」 | 避免二刷/错题重做把真实水平刷高 |
| 错题本 | 交卷自动入库，连续 2 次答对转已掌握 | 无需手动抄题；重做有明确退出条件 |
| 云同步 | 独立 `easysail-exam-reading.json`；题库不进快照 | 题库可从资源重导，快照只存用户数据 |
| 图标 | lucide-react（`Newspaper` / `Timer` / `BarChart3`），无 emoji | 遵守 `docs/开发规范.md` |

## 四、题库与数据模型

### 4.1 题库构建：从已下载真题到 reading-bank.json

#### 4.1.1 数据源与产物

仓库内维护一个运行时产物；应用只读 `reading-bank.json`：

```
src/assets/exam-reading/
  reading-bank.json        # 20 篇 / 100 题，?raw 导入
scripts/
  extract-reading-pdfs.py  # 一次性：PDF → 文本（作者本机跑，不进 CI）
  build-reading-bank.mjs   # 解析集解析 + PDF 合并 + 校验 + 生成 JSON
reading-source/            # 中间产物：PDF 文本、draft.json、review.csv（.gitignore）
```

外部数据目录 `/Users/cgy/data/work-buddy/考研英语二真题/` 只在**构建期**读取。脚本用 `--source` 或环境变量 `READING_SOURCE_DIR` 指定；生成的 JSON 提交进仓库后，CI 与应用运行时都不再依赖该目录。

原目录按**只读**对待：不要修改下载的 md/PDF；所有修正写入 `build-reading-bank.mjs` 的 `CORRECTIONS` / `PASSAGE_SUPPLEMENTS` 表与 `review.csv`，保持原始出处可追溯。TSV 仅作为可选人工审阅导出，当前实现不依赖它。

`package.json` 新增：

```json
"build:reading": "node scripts/build-reading-bank.mjs"
```

> `reading-bank.json` 必须始终存在（可以是 `passages: []` 的空题库），否则 `?raw` 导入会让构建直接失败。构建脚本在源数据缺失时生成空题库并警告，不删除已有文件；页面按「题库未加载」空态处理。

#### 4.1.2 字段来源映射

| bank 字段 | 来源 | 处理方式 |
|---|---|---|
| `passage.key` / `year` / `textNo` | PDF 的 `Text 1–4` + 年份 | 以标题、题号锚点切分 |
| `passage.paragraphs` | PDF 阅读原文 | 文本层抽取 + 去页眉页脚 + 校勘表 |
| `passage.title` | 解析集 `### Text N（21-25）— 主题：…` | 取「主题：」后的中文短语 |
| `passage.topic` | README 的五年题材分类 | 人工归为科技 / 环境 / 社会 / 公共机构 / 商业 / 教育 / 其他 |
| `question.stem` | PDF 题干 | 题号 21–40 的题干块 |
| `question.options` | PDF 的 A–D 四个选项 | 按选项字母切分，保留原文顺序 |
| `question.answer` | 解析集 `**NN. [X] …**` + README 速查表 + PDF 答案键（2024/2025/2026） | 逐题比对；PDF 有答案键时三方比对，冲突进复核清单 |
| `question.explanation` | 解析集的 `解析：…` | 原文照录，不改写 |
| `question.distractors` | 解析集的 `干扰项：…` | 原文照录 |
| `question.locateHint` | 解析集的 `定位：…` | 原文照录（含引文） |
| `question.locatePara` | 从 `locateHint` 解析 | `第 N 段` / `末段` / `倒数第 N 段`；解析不了填 0 |
| `question.qtype` | 解析集的 `考点：…` | 映射表；未知归 `other` 并复核 |
| `question.answerNote` | 解析集的 `⚠️ 存疑` / `说明` / `校勘提示` | 人工确认后写入 |
| `question.disputed` | README + 解析集 | 2025 Q30 = 1；其余 0 |
| `question.answerAlt` | README 的争议双方 | 仅在 `disputed=1` 时填写（2025 Q30 = D） |
| `question.sourceRef` | 文件名 + 题号；PDF 文件名 + 页码 | 自动生成，便于追溯 |
| `passage.sourceRef` | PDF 文件名 + 起始页 | 自动生成 |

#### 4.1.3 半自动构建流程

1. **冻结数据源**：记录 README 的整理日期 `2026-10-31`、5 个解析 md、README 与 8 个 PDF 的 sha256，写入 `reading-bank.json` 的 `dataset` 字段；题库版本与数据集版本一一对应。
2. **PDF 抽文本**（一次性）：`python3 -m pip install pypdf`，运行 `scripts/extract-reading-pdfs.py --source <dir> --out reading-source/pdf-text/`。输出保留 `=== PAGE n ===` 页码标记，便于回填 `sourceRef`。若某页是纯图片抽不出文本，该篇退回人工录入，并记入复核清单。若本机无法安装 pypdf，可用 PDF 阅读器导出文本或手工复制；抽取脚本只是加速，最终以 `build-reading-bank.mjs` 的修正表与人工校对结果为准。
3. **拆分解析集 Markdown**：`build-reading-bank.mjs` 的解析集解析部分只截取 `## Section II 阅读理解 Part A` 到 `## Part B` 之间的内容，按 `### Text N（21-25）— 主题：…` 与 `**NN. [X] …** — 考点：…` 切块。需同时兼容 2026 的「定位/解析/干扰项」同行分号格式，以及 2022–2025 的换行格式。
4. **解析 PDF**：按 `Text 1–4` 与题号 21–40 切分原文、题干、选项；去掉页眉页脚、行内断词（`exam- ple` → `example`）和页码。无法高置信切分的块标 `needs_review=1`，不猜。
5. **合并与交叉校验**：
   - 用 `year + 题号` 关联解析集与 PDF；
   - 比对解析集的 `[X] 正确项文本` 与 PDF 第 X 个选项（归一化大小写/标点后比较），不一致 → 复核（这条能直接抓出 2023 Q29 这类选项顺序差异）；
   - 比对解析集答案、README 速查表、PDF 答案键（如有）三方；
   - 校验每篇 5 题、每题 4 个非空选项、`locatePara` 在段落范围内；
   - 输出 `reading-source/review.csv`，列出所有 `needs_review` 与冲突原因。
6. **人工校对**（关键，不可省）：按 `review.csv` 逐条修复，重点：
   - 2025 Text 1 两处 OCR 讹误：`often well above 70%` → `20%`；`benefits some of these workers, such as cooks and dishwashers` → 补全 `such as waiters, but not others, such as cooks and dishwashers`；
   - 2025 Text 4 第 1–2 段整段重复，按解析集的 6 段定位去重；
   - 2023 Text 2 Q29 选项顺序以试卷 PDF 为准（A 旅游引领 / B 历史意义 / C 气候研究资助 / D 当地收入，答案 B）；
   - 2026 Text 1 的逗号粘连统一修正（不影响答题）；
   - 2025 Q21 采信 B（个别来源作 C，`disputed=0`，仅写 `answerNote`）；2025 Q30 采信 C、`answerAlt='D'`、`disputed=1`；2022 Q39 采信 C（网友版作 D，`disputed=0`，仅写 `answerNote`）；2026 Q30 虽有讨论，但四方一致 A，不标 disputed。
7. **生成产物**：人工校对结果直接进入 `reading-bank.json`（脚本同时输出 `reading-source/draft.json` 与 `review.csv` 便于检查）；如需人工表格审阅，可额外导出 TSV（可选，不参与运行时）。
8. **构建 JSON**：`npm run build:reading` 做 4.1.5 的强校验并输出 `reading-bank.json`；失败即非零退出。
9. **应用内抽查**：随机抽 2 篇，对照 PDF 检查段落、题干、选项、答案、解析、定位；通过后再批量生成其余年份。

#### 4.1.4 TSV 格式（可选审阅导出）

**`reading-passages.tsv` 列**（制表符分隔，首行表头）：

| 列 | 说明 |
|---|---|
| `passage_key` | 稳定键，`YYYY-tN`，如 `2022-t1` |
| `year` | 2022–2026 |
| `text_no` | 1–4 |
| `title` | 主题短语（来自解析集，可为空） |
| `topic` | 题材：科技 / 环境 / 社会 / 公共机构 / 商业 / 教育 / 其他 |
| `difficulty` | 1 易 / 2 中 / 3 难（人工标注） |
| `paragraphs` | 段落用两个竖线字符分隔（示例见下方） |
| `translation` | 段落译文，分隔符同上；可为空 |
| `source_ref` | PDF 文件名 + 起始页，如 `2022-英语二-试题.pdf p.3` |

**`reading-questions.tsv` 列**：

| 列 | 说明 |
|---|---|
| `question_key` | 稳定键，`YYYY-tN-qM`，如 `2022-t1-q1` |
| `passage_key` | 逻辑外键，不建 FK |
| `seq` | 1–5 |
| `stem` | 题干（PDF 原文） |
| `options` | 4 个选项用两个竖线字符分隔，不带 `A.` 前缀（脚本容错剥离） |
| `answer` | 主答案 `A`–`D` |
| `answer_alt` | 争议题的第二答案；非争议题为空 |
| `disputed` | 0/1；1 表示答案存在未决分歧 |
| `qtype` | `detail` / `infer` / `main` / `vocab` / `attitude` / `example` / `other` |
| `locate_para` | 定位段落号（1-based，主旨题可填 0） |
| `locate_hint` | 解析集的原始定位描述（含引文） |
| `explanation` | 解析：正确项理由 |
| `distractors` | 干扰项分析；缺失时进复核清单 |
| `answer_note` | 答案说明/存疑来源；争议题必填 |
| `source_ref` | 解析集文件名 + 题号，如 `2022-考研英语二真题.md#Text1-Q21` |
| `difficulty` | 1 易 / 2 中 / 3 难 |

行格式示意（制表符分隔，正文/选项内部用 `||`）：

```text
2022-t1	2022	1	气候友好型鸡蛋与再生农业	环境	2	Paragraph 1 text||Paragraph 2 text||Paragraph 3 text		2022-英语二-试题.pdf p.3
2022-t1-q1	2022-t1	1	According to Paragraph 2, ...	Option A text||Option B text||Option C text||Option D text	D		0	detail	1	第 1 段「This all seems random, but it's by design」	by design ↔ specially designed farms	A（低成本）与原文 $8 a dozen 矛盾...		2022-考研英语二真题.md#Text1-Q21	2
```

> TSV 单元格内不能有制表符；解析里的换行用字面 `\n`；解析里如出现 `||`，用 `\|` 转义，构建脚本统一还原。

#### 4.1.5 构建脚本强校验

任一条失败即非零退出，输出具体行号：

1. 年份 5 个、每年 4 篇、每篇 5 题；`passage_key` / `question_key` 符合正则且不重复。开发期可加 `--allow-partial` 只校验已有篇目；正式题库（5 年齐全）不带该参数。
2. `question_key` 必须等于 `${passage_key}-q${seq}`。
3. 段落 3–8 段，`translation` 为空或与段落数一致；正文不得包含页眉、页码、`=== PAGE` 等抽取残留。
4. 每题 4 个非空选项，答案 A–D，`locate_para` 在 0 与段落数之间；`locate_hint`、`source_ref` 非空。
5. `qtype` 在枚举内，`explanation` 非空；`distractors` 缺失时打印警告并计入复核清单。
6. `disputed=1` 时 `answer_alt` 必须是 A–D 且不等于 `answer`，`answer_note` 非空；非争议题 `answer_alt` 必须为空。
7. 带 `--source` 时，额外读取 README 的阅读 Part A 答案速查表，与题库 JSON 逐题比对；除 `disputed=1` 外不一致即失败。
8. 词数由脚本按空白切分计算并写入 JSON，不手填。

#### 4.1.7 工作量与年度维护

- 脚本（PDF 抽取 + 解析集解析 + 合并校验）：1–2 天。
- 人工校对（20 篇 × 20–30 min，含校勘/争议题）：8–12 小时。合计约 3–4 天，而不是从零录入的 25–30 小时。
- 若某年 PDF 无文本层、只能人工录入，该年按 1–1.5 h/篇追加。
- 年度维护：每年 12 月底把新一年解析集与试卷 PDF 放进数据目录 → 跑 4.1.3 的流程 → `version + 1` → 应用内抽查 1 篇；计划池按题库年份倒序自动分层（默认最近 5 年：2 年套卷、1 年限时、其余精读），旧年份保留作二刷。

### 4.3 题库导入策略

`src/lib/exam-reading-db.ts` 暴露 `importReadingBank(force?: boolean)`：

1. `import raw from '../assets/exam-reading/reading-bank.json?raw'` 后 `JSON.parse`（与 `vocab-phonetics.ts` / `vocab-examples.ts` 一致，避免 TS 对 20 篇正文做字面量类型推断）。
2. 读 `exam_reading_profile.bank_version`。`raw.version <= 当前版本 && 题库非空 && !force` → 跳过。
3. 逐篇 `INSERT INTO exam_reading_passages (...) VALUES (...) ON CONFLICT(passage_key) DO UPDATE SET ...`，保留自增 `id`（attempts 引用它）。
4. 查 `SELECT id, passage_key` 建立映射，再批量 upsert 题目（`ON CONFLICT(question_key) DO UPDATE`）；同时覆盖 `answer_alt` / `disputed` / `answer_note` / `locate_hint` / `distractors` / `source_ref`，旧 JSON 缺字段时按空值容错。
5. 更新 `bank_version`。
6. 题库中已删除的 key 不物理删除：`archived=1`，历史 attempts 仍可复盘。
7. 任一步失败：保留旧数据，返回 `{ imported: false, error }`，页面显示「题库未加载」并提供重试；不阻塞其他模块（独立 DB 连接）。
8. 100 题用多值 INSERT 分批（每批 50 行 × 11 列），避免 100 次 IPC；不手动开长事务（`tauri-plugin-sql` 连接池下 BEGIN/COMMIT 可能落到不同连接，见 `exam-vocab-db.ts` 的注释）。

## 五、刷题时间设计（与考试时间对齐）

这是本方案的核心。时间对齐分三层，任何一层都不能只做成「显示一个倒计时」。

### 5.1 三层对齐总览

| 维度 | 考场事实 | 功能参数 |
|---|---|---|
| 日期 | 2026-12-19（默认 `exam_profile.exam_date`） | 倒计时 + 三阶段排期 + 剩余篇数估算 |
| 时段 | 英语二 14:00–17:00；阅读块约 14:15–15:25 | 建议 14:15 开始；记录是否在考场时段；统计时段正确率 |
| 单篇时长 | 17.5 min/篇（70 min ÷ 4） | 标准 18 min，冲刺 15 min；到点自动交卷 |
| 套卷时长 | 阅读 Part A 70 min | 套卷 70 min；到点自动交卷；满分 40 |
| 判分 | 20 题 × 2 分 | `score = correct_count × 2`，单篇满分 10 |
| 做题节奏 | 读文 6–7 min + 5 题 10 min + 检查 1–2 min | 计时器节点提示 + 每题用时统计 |
| 复盘 | 考场没有复盘时间 | 复盘不计入 session 用时，单独记录错因 |

### 5.2 时长对齐：三档训练

| 模式 | key | 范围 | 限时 | 交卷方式 | 适用阶段 |
|---|---|---|---|---|---|
| 精读 | `close` | 单篇 5 题 | 不限时，正向计时 | 手动 | 一刷：读懂文章、查生词、拆长难句 |
| 限时单篇 | `timed` | 单篇 5 题 | 18:00（可切 15:00） | 到点自动锁定并交卷 | 二刷：练定位与选项辨析 |
| 套卷 | `set` | 1 年 4 篇 20 题 | 70:00 | 到点自动交卷 | 考前：连续 70 分钟不被打断 |
| 错题重做 | `wrong` | 单篇错题 | 不限时 | 手动 | 复盘后：只重做错题，连续 2 次对转已掌握 |

参数依据：

- **18 min** 是单篇上限：4 × 18 = 72 min，接近考场 70 min 预算；超过 18 min 会挤压完形/新题型/写作，不作为训练档位。
- **15 min** 是冲刺档：适合二刷后期，训练「读文 6 min + 每题 1.5 min」。
- **70 min** 套卷：与全卷时间表严格一致；不做「80 min 宽松套卷」，避免平时节奏松、考场做不完。
- 精读不设限时，但正向计时会显示「已用 32:10」，用于识别自己读文过慢的问题。

### 5.3 时段对齐：14:15 进入阅读块

考场阅读块的时间推导：

```
14:00 开考
14:00–14:15 完形填空（建议顺序）
14:15–15:25 阅读 Part A（70 min）
15:25–15:40 阅读 Part B
15:40–16:00 翻译
16:00–16:45 写作
16:45–17:00 涂卡 / 检查
```

功能规则：

1. 今日计划卡显示「建议今天 **14:15** 开始 · 限时 18:00」；套卷显示「建议在考试同星期几的 **14:15** 开始 · 70:00」。
2. 开始练习时，若当前本地时间不在 `exam_slot_start`–`exam_slot_end`（默认 14:00–17:00）内，开始面板显示一行非阻断提示：
   「当前 20:30，非英语二考试时段。建议 14:15 开始以匹配考场状态。」提供「仍然开始」按钮。
3. `exam_reading_sessions.in_exam_slot` 在开始时刻计算并落库（本地时区）；不因中途跨过 17:00 而改变。
4. 统计页展示：
   - 考场时段练习占比 = `in_exam_slot=1` 的已交卷 session / 已交卷 session。
   - 考场时段 vs 非考场时段的正确率对比（同时显示样本数 n，避免小样本误判）。
5. `slot_hint=0` 可关闭提示，但**仍然记录** `in_exam_slot`，统计不受影响。
6. 不做硬性时间锁：上班族可能只能在晚上练，强制锁时段会让功能不可用。提示 + 统计是更合理的约束。

### 5.4 日期对齐：倒计时驱动排期

#### 5.4.1 数据来源

- 考试日：直接调用 `fetchExamProfile()` 读 `exam_profile.exam_date`（默认 `2026-12-19`）。**不复制字段**，用户在考研计划里改日期，阅读计划自动跟随。
- 今天：`localDateStr()`；剩余天数 `D = daysUntil(examDate, today)`，与 `ExamVocabPage` 同一算法。
- 若 `exam_date` 为空：只显示题库与统计，计划卡提示「请先在考研计划中设置考试日」。
- 若 `D < 0`：显示「2026 考研已结束」，计划区只读；题库与历史统计仍可用，设置里可更新考试日后重新排期。

#### 5.4.2 阶段划分

> 下表年份以 2022–2026 题库为例；实际按 5.4.3 的规则按题库年份动态取。

| 剩余天数 D | 阶段 | 训练重点 | 题库池 |
|---|---|---|---|
| D > 35 | 精读期 | 读懂、生词、长难句、逐题定位 | 最早 2 年（2022、2023，8 篇） |
| 15 < D ≤ 35 | 限时期 | 18 min/篇，练定位与排除 | 次新 1 年（2024，4 篇） |
| 3 < D ≤ 15 | 套卷期 | 70 min 整套，连续 4 篇 | 最近 2 年（2025、2026，2 套） |
| D ≤ 3 | 考前收尾 | 只重做错题 + 1 篇旧题保持手感 | 不刷新题 |

阈值理由：

- 35 天：8 篇精读 × 2 天/篇 = 16 天，留出缓冲；再晚就没有精读时间。
- 15 天：2 套模考 + 每套 5–6 天复盘，刚好覆盖考前两周。
- 3 天：不再接触新题，避免考前发现大量错误打击状态。

#### 5.4.3 题库池分配

按题库实际年份倒序取，**不写死 2022–2026**：

```
years = 题库年份倒序            // [2026, 2025, 2024, 2023, 2022]
mockYears  = years[0..1]        // 2026, 2025：考前套卷
timedYear  = years[2]           // 2024：限时单篇
closeYears = years[3..]         // 2023, 2022：精读
```

- 若某年题库缺失，顺延取下一个可用年份；不足 5 年时按实际数量降级。
- `exam_reading_profile.mock_years` 非空时以用户设置为准（设置页可改）。
- 阶段池只是**推荐优先级**，题库 Tab 里任何一篇都可手动开始；计划不锁题。

#### 5.4.4 今日推荐算法

```
1. D = examDate - today
2. phase = D<=3 ? final : D<=15 ? set : D<=35 ? timed : close
3. 当前池 = 按 phase 取 5.4.3 的年份集合
4. 当前池未完成项：
   close/timed：该年 4 篇中，没有已交卷 session 覆盖的篇目（按年份、Text 升序）
   set：该年没有已交卷 set session 的年份
5. 当前池为空 → 自动进入下一池（提前完成不空等）
6. 今日推荐 = 当前池第一个未完成项
7. 预计完成日 = today + 剩余练习单元数 × 当前阶段节奏
   close 2 天/篇、timed 4 天/篇、set 7 天/套
8. 预计完成日 > examDate - 3 → 提示「进度偏慢，建议今天补 1 篇」；否则「进度正常」
```

`final` 阶段：推荐错误题数最多的 1 篇做错题重做 + 1 篇已完成篇目重读，不推荐新题。

#### 5.4.5 以 2026-10-30 为起点（D-50）的参考排期

| 阶段 | 日期 | 内容 | 节奏 | 单次用时 |
|---|---|---|---|---|
| 精读 | 10/30–11/13 | 2022、2023 共 8 篇 | 约 2 天/篇（8 篇 15 天完成） | 30–40 min |
| 限时 | 11/14–12/03 | 2024 共 4 篇 | 4 天/篇（18 min 做 + 精析 + 错题二刷） | 18 min |
| 套卷 1 | 12/05（周六）14:15 | 2025 整套 4 篇 20 题 | 70 min + 12/06–12/10 复盘 | 70 min |
| 套卷 2 | 12/12（周六）14:15 | 2026 整套 4 篇 20 题 | 70 min + 12/13–12/15 复盘 | 70 min |
| 考前收尾 | 12/16–12/18 | 错题重做 + 1 篇旧题 | 每天 30 min，不刷新题 | 30 min |
| 考试 | 12/19（周六）14:00–17:00 | 英语二 | — | 180 min |

> 12/04 为缓冲日；若精读期因复盘延误，最多占用 11/14 一天，限时期顺延，套卷日期不变。

### 5.5 计时实现规则

1. **墙钟优先**：开始会话时算出 `deadline_at = started_at + limit_seconds`。前端每秒用 `Date.now()` 重算剩余，不做「state - 1」累减。后台标签页定时器被节流、系统休眠、切换窗口都不会让剩余时间变多。
2. **不提供暂停**：考场没有暂停。切到其他页面、最小化、切 Tab，计时继续；`visibilitychange` 回到前台时立即重算，已超时则自动交卷。
3. **到点锁定**：`timed` / `set` 在剩余 ≤ 0 时自动提交一次（用 ref 防重复提交），并标记 `overtime=1`。交卷后进入复盘，不允许再改答案。
4. **精读正向计时**：`close` / `wrong` 模式从 `started_at` 起正向显示 `mm:ss`，手动交卷；`elapsed_ms` 取交卷时刻减开始时刻。
5. **每题用时**：题目可见时记录进入时间，切题/作答时累加到 `duration_ms`；页面隐藏期间不计入单题用时（但计入会话总时长），避免休眠产生几小时的「单题用时」。
6. **退出恢复**：开始即写 `exam_reading_sessions`（`status='ongoing'`），每次作答即时 upsert `exam_reading_attempts`。下次进入模块：
   - 未超时：弹「继续上次练习（剩余 12:34）/ 作废」。
   - 已超时：弹「上次限时练习已超时，按已答内容交卷 / 作废」；交卷后 `overtime=1`，未答题按 0 分处理。
   - 同一时间只允许一个 `ongoing` 会话；开始新练习前必须先处理旧会话。
7. **节奏提示**：`timed` 模式在第 7 分钟显示一次轻提示「已用 7 分钟，建议开始作答（剩余 11 分钟）」；不弹窗、不打断输入。
8. **时间存储**：`started_at` / `deadline_at` / `submitted_at` 统一 ISO UTC；`in_exam_slot` 用本地时间判断；按日统计用 `date(started_at,'localtime')`（与背单词模块一致，避免 UTC 跨日）。

## 七、判分与统计口径

### 7.1 判分

- `is_correct = user_answer === question.answer || (question.disputed && user_answer === question.answer_alt)`；仅比较字母，选项文本不参与判分。
- `answered_count` 不含 `user_answer=''`；`correct_count` 只统计答对。
- 单篇 `score = correct_count × 2`（满分 10）；套卷 `score = correct_count × 2`（满分 40）。
- 未答按 0 分，但单独统计「未答」数量，便于区分「不会」与「没做完」。
- `overtime=1` 只表示到时交卷/超时，不代表答错；限时完成率按它计算。
- 交卷时，答错与未答都进错题本：答错 `reason` 留空待用户标注；未答默认 `reason='time'`。
- 争议题（`disputed=1`）两个答案都判对；复盘显示「主答案 C / 另一来源 D」与 `answer_note`，统计页单独提示争议题数量。
- 错题模式下不显示考试分数，只显示「答对 X / Y」。

### 7.2 统计口径

| 指标 | 口径 |
|---|---|
| 首刷正确率 | 每道题**最早一次**在已交卷会话中的作答为样本，正确数 / 已作答数 |
| 含重做正确率 | 所有已交卷会话的 attempts 为样本，正确数 / 已作答数 |
| 累计篇数 | 已交卷 session_questions 覆盖的不同 passage 数（套卷计 4 篇） |
| 累计题数 | 首刷 attempts 数（不含未答） |
| 未答 | 已交卷 session_questions 中没有 attempt 的题数 |
| 平均每题用时 | `SUM(duration_ms) / attempts 数` |
| 限时完成率 | `mode IN ('timed','set') AND overtime=0` 的会话数 / 同模式会话数 |
| 套卷平均分 | `mode='set'` 的 `score` 平均值（满分 40） |
| 考场时段占比 | `in_exam_slot=1` 的已交卷会话 / 已交卷会话 |
| 按年份 / 题型正确率 | 首刷 attempts JOIN questions JOIN passages 后 GROUP BY |
| 错因分布 | `exam_reading_wrongbook.reason` GROUP BY（空串归为「未标注」） |
| 争议题 | `questions.disputed=1` 的题数，以及其中选主答案/第二答案的分布 |

实现取舍：

- 数据量很小（20 篇、最多几百次会话、几千条 attempts），**首刷去重在前端做**：按 `answered_at` 升序取每题第一条，再计算指标；其余聚合用 SQL。
- 所有统计查询过滤 `sessions.status='submitted'`、`questions.archived=0`；`abandoned` 会话的 attempts 保留但不进统计。
- 统计按本地日期分组时统一 `date(started_at,'localtime')`，与背单词模块的 `fetchTodayStats` 保持一致。

## 九、云同步

新增独立文件 `easysail-exam-reading.json`，不与其他模块混在一个文件：

```json
{
  "version": 1,
  "exportedAt": "2026-11-02T06:00:00.000Z",
  "reading": {
    "profile": { "...": "..." },
    "sessions": [],
    "sessionQuestions": [{ "sessionId": "...", "questionKey": "2022-t1-q1", "sortOrder": 0 }],
    "attempts": [{ "sessionId": "...", "questionKey": "2022-t1-q1", "userAnswer": "B", "isCorrect": true, "durationMs": 96000, "flagged": false, "answeredAt": "..." }],
    "wrongbook": [{ "questionKey": "2022-t1-q3", "wrongCount": 1, "reason": "locate", "...": "..." }]
  }
}
```

要点：

1. **题库不进快照**：passages/questions 可从 `reading-bank.json` 重导，避免云文件膨胀与版权内容外溢。
2. **用 `question_key` 关联**：跨机器恢复时自增 `question_id` 可能不同；恢复流程先导入题库，建立 `key → id` 映射，再写 attempts/wrongbook/sessionQuestions。未知 key 跳过并计数，提示「N 条记录因题库版本不一致被忽略」。
3. 恢复顺序：`importReadingBank(true)`（题库为空时）→ 清空 sessions/sessionQuestions/attempts/wrongbook → 批量插入 → 覆盖 profile。用「旧快照备份 + 失败还原」的策略，与 `replaceExamVocabData` 一致。
4. `registerExamReadingGetter` 注册到 `cloud.ts`；store 维护 `readingDirty`，无写入时返回 `null`，避免每 60 秒全量序列化。
5. 自动同步循环末追加：
   ```ts
   const reading = await _getExamReading?.()
   if (reading) await saveExamReadingToCloud(reading)
   ```
6. 浏览器模式（非 Tauri）沿用 `localStorage` fallback，与现有 `saveCollectionToCloud` 一致。

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 真题正文版权 | 公开发布可能侵权 | 题库与代码分离；个人使用内置，公开发布改为「本地导入」；文档标注来源 |
| PDF 文本层/OCR 讹误 | 原文错、定位段号错 | 4.1.3 校勘表 + 人工复核；2025 Text 1 两处修正、2025 Text 4 去重；抽不出文本的篇目回退人工录入 |
| 答案版本冲突 | 用户被误判 | 解析集/README/PDF 答案键三方比对；`disputed + answer_alt` 双答案判对；`answer_note` 显示来源 |
| 题库校对遗漏 | 答案/解析错，练习白做 | 构建脚本强校验 + README 速查表逐题比对 + 应用内「本题有误」下架 |
| 后台/休眠计时漂移 | 限时训练不公平 | 墙钟 `deadline_at`，回到前台重算；不用 tick 累减 |
| 退出丢作答 | 套卷中断白做 | 开始即建 session、每题即时 upsert、重开恢复/补交 |
| SQLite 写锁 | 导入/交卷失败 | 题库分批多值 INSERT；作答单条写；不手动开长事务 |
| 迁移回退 | `VersionMissing`，数据层全挂 | 只新增 v3，绝不改 v1/v2；CI 构建验证 |
| 新页面漏接线 | 顶部串入日历/看板 | 严格按 8.2 的 4 处同步，重点检查 `hideChrome` |
| 云恢复题库版本不一致 | 题目对不上 | 快照用 `question_key`；恢复前先导题库；未知 key 跳过并提示 |
| 统计口径混淆 | 二刷看起来正确率很高 | 默认首刷口径；UI 明确标注「首刷 / 含重做」 |
| 精读占用过多时间 | 挤压其他题型 | 精读池只在 D>35 推荐；计划落后时自动优先保套卷 |
| 长文排版差 | 阅读疲劳 | 文章最大宽度 680–720px、行高 1.8、字号三档、段落号可定位 |
